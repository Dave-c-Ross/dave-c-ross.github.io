You might, for multiple reasons, need to exit your pod from a different IP then the node primary IP. In that case, you will need EgressIPs. 

Here is the steps we will take:
- [X] Configure the node for a secondary interface using a NodeNetworkConfigurationPolicy
- [X] Use the Tuned operator to enable ip forwarding, so we can use a secondary if.
- [X] Define an EgressIP pool of ips that will be assigned to every node
- [X] Create 2 namespaces, one with a prod label (which will use a different egress ip), one without it.
- [X] Spaw 2 pods, one per namespace, and perform some tests while running tcpdump in the background.


### Configure the node for a secondary interface using a NodeNetworkConfigurationPolicy
```
# In order for a node to get assigned an egress IP, you need to label it as such.
# oc patch node big-bertha --type merge -p '{"metadata":{"labels":{"k8s.ovn.org/egress-assignable":""}}}'

---
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: nncp-yan-a
spec:
  nodeSelector:
    node-role.kubernetes.io/worker: ""
  desiredState:
    interfaces:
      - name: eno3.170
        type: vlan
        state: up
        vlan:
          base-iface: eno3
          id: 170
        ipv4:
          address:
            - ip: 192.168.170.5
              prefix-length: 24
          dhcp: false
          enabled: true
```

#### Now let's test our network config:
  1. OC debug using a tcpdump: `oc debug node/big-bertha` then `tcpdump -i eno3 -nn -e src 192.168.170.5 and dst 192.168.170.1`
  2. ssh on the node and generate some trafic we can see in the dump: `nc -s 192.168.170.6 -zv 192.168.170.1 443`


### Use the Tuned operator to enable ip forwarding, so we can use a secondary if
```
---
# If using a secondary interface, ip_forward will need to be enable.
apiVersion: tuned.openshift.io/v1
kind: Tuned
metadata:
  name: enable-ip-forward
  namespace: openshift-cluster-node-tuning-operator
spec:
  profile:
  - name: enable-ip-forward
    data: |
      [main]
      summary=Enable IPv4 forwarding for EgressIP
      include=openshift-node

      [sysctl]
      net.ipv4.ip_forward=1
  recommend:
  - priority: 20
    profile: enable-ip-forward
    match:
    - label: node-role.kubernetes.io/master

```


### Define an EgressIP pool of ips that will be assigned to every node
```
---
# Now define the EgressIP, you will need enough IP for all your nodes. Also, define what 
# will be the label used for namesapces wich will contain pod that will use an EgressIP. 
# For many EgressIP vs namespace, you'll need to create multiple EgressIP object.
apiVersion: k8s.ovn.org/v1
kind: EgressIP
metadata:
  name: egressips-prod
spec:
  egressIPs:
  - 192.168.170.150
  - 192.168.170.151
  - 192.168.170.152
  namespaceSelector:
    matchLabels:
      env: prod
```
> You should see your ip assigment when loged into the node: `ip a | grep 192`


### Create 2 namespaces, one with a prod label (which will use a different egress ip), one without it
```
---
# Namespace used to run a pod which will use the default egress ip, the primary node IP
apiVersion: v1
kind: Namespace
metadata:
  labels:
    kubernetes.io/metadata.name: userspace-egress-0
  name: userspace-egress-0

---
# Namespace used to run a pod which will use an alternaed egress ip, based on label.
apiVersion: v1
kind: Namespace
metadata:
  labels:
    env: prod  # <----- This is needed so pod in that namespace will have an EgressIP
    kubernetes.io/metadata.name: userspace-egress-1
  name: userspace-egress-1




```

### Spaw 2 pods, one per namespace, and perform some tests while running tcpdump in the background
```
---
# In each of the following container, run a curl and see from tcpdump or other mecanisum that
# it is working. In my homelab, I'll curl on my gateway `curl https://192.168.170.1 -k`
---
apiVersion: v1
kind: Pod
metadata:
  name: test-with-egress-ip
  namespace: userspace-egress-0
spec:
  containers:
    - resources: {}
      stdin: true
      terminationMessagePath: /dev/termination-log
      stdinOnce: true
      name: test
      securityContext:
        capabilities:
          drop:
            - MKNOD
      imagePullPolicy: Always
      terminationMessagePolicy: File
      tty: true
      image: registry.access.redhat.com/ubi9/ubi

---
apiVersion: v1
kind: Pod
metadata:
  name: test-with-egress-ip
  namespace: userspace-egress-1
spec:
  containers:
    - resources: {}
      stdin: true
      terminationMessagePath: /dev/termination-log
      stdinOnce: true
      name: test
      securityContext:
        capabilities:
          drop:
            - MKNOD
      imagePullPolicy: Always
      terminationMessagePolicy: File
      tty: true
      image: registry.access.redhat.com/ubi9/ubi
```

## Now let's test the whole setup !
  1. Open a debug console on the node `oc debug node/big-bertha` 
  2. Start a tcpdump session on the primary interface and filter the destination: `tcpdump -i eno1 -nn -e src 192.168.170.1`
  3. From pod `test-with-egress-ip` running in namespace `userspace-egress-0`, make a curl request on your target: `curl https://192.168.170.1 -k`. You should see trafic going out from your primary if.
  4. Start a tcpdump session on the primary interface and filter the destination: `tcpdump -i eno1 -nn -e src 192.168.170.1`
  5. From pod `test-with-egress-ip` running in namespace `userspace-egress-1`, make a curl request on your target: `curl https://192.168.170.1 -k` You should see trafic going out from your secondary if on VLAN 170.
